# Storyboard — Video 1: Skills as Task-Specific Context

**Target duration:** 6:00  
**Visual motif:** gray task cards, indigo skill cards, a context-window meter.

## Slide 1 — One request, four manuals

- **Main message:** Always-on guidance gives every task more context than it
  may need.
- **Minimal on-screen text:** “One task ≠ every manual”
- **Recommended visual:** A stakeholder-update card entering a prompt already
  filled by four thick skill manuals.
- **Narration segment:** Script 0:00–0:50.
- **Speaker notes:** Name all four repository skills once.
- **Animation:** Manuals enter one at a time; context meter fills.
- **Technical accuracy notes:** Do not claim context volume alone degrades
  quality; present it as cost, relevance, and conflict risk.
- **Instructor review:** Confirm the incident continuity from Module 1.

## Slide 2 — Skill definition

- **Main message:** A skill packages reusable model-facing guidance.
- **Minimal on-screen text:** “Reusable guidance, loaded for a task”
- **Recommended visual:** Skill card with procedure, evidence rules, edge cases,
  and output contract tabs.
- **Narration segment:** Script 0:50–1:45.
- **Speaker notes:** Emphasize that loading text performs no business action.
- **Animation:** Reveal the four tabs, then an “instructions only” badge.
- **Technical accuracy notes:** Avoid equating all skill formats with this
  repository's simplified implementation.
- **Instructor review:** Approve definition wording.

## Slide 3 — Component placement

- **Main message:** Skills are for selective know-how, not every harness need.
- **Minimal on-screen text:** “Guidance • Data • Action • Gate • Acceptance”
- **Recommended visual:** Five bins labeled skill, retrieval, tool, hook, and
  evaluator; example requirements drop into each.
- **Narration segment:** Script 1:45–2:40.
- **Speaker notes:** Permission appears as a sixth callout beside the hook.
- **Animation:** Sort one example at a time.
- **Technical accuracy notes:** A business rule may appear as explanatory skill
  text while still requiring runtime enforcement elsewhere.
- **Instructor review:** Verify alignment with Modules 3–5.

## Slide 4 — Progressive disclosure

- **Main message:** Route with compact metadata before loading detailed text.
- **Minimal on-screen text:** “Metadata → instructions → optional resources”
- **Recommended visual:** Three nested layers; highlight only the first two as
  implemented by the demo.
- **Narration segment:** Script 2:40–3:45.
- **Speaker notes:** Say explicitly that the repository does not auto-run
  scripts or recursively load resources.
- **Animation:** Open each layer; apply a “course demo” bracket to layers one
  and two.
- **Technical accuracy notes:** The third layer describes a broader format, not
  demonstrated behavior.
- **Instructor review:** Keep the local-profile qualifier visible.

## Slide 5 — Discovery is not success

- **Main message:** Found, selected, loaded, followed, and accepted are separate
  events.
- **Minimal on-screen text:** “Found → selected → loaded → followed → accepted”
- **Recommended visual:** Five checkpoint gates with separate evidence badges.
- **Narration segment:** Script 3:45–4:35.
- **Speaker notes:** Pause after “loaded” and ask what it proves.
- **Animation:** Advance one checkpoint per statement.
- **Technical accuracy notes:** Do not infer following or acceptance from a
  loader trace.
- **Instructor review:** None.

## Slide 6 — Eager versus on-demand

- **Main message:** Progressive disclosure exchanges context breadth for an
  extra routing step and new failure modes.
- **Minimal on-screen text:** Two flow diagrams; no verdict label.
- **Recommended visual:** One-call eager path beside two-call skill path.
- **Narration segment:** Script 4:35–5:30.
- **Speaker notes:** Use “may” for token and quality effects.
- **Animation:** Trace each path, then reveal tradeoff icons.
- **Technical accuracy notes:** Measure total tokens over both on-demand calls.
- **Instructor review:** Reject any “skills always save tokens” wording.

## Slide 7 — Focused unit of know-how

- **Main message:** A skill should have one coherent reusable responsibility.
- **Minimal on-screen text:** “Focused • reusable • selectable”
- **Recommended visual:** A clean skill card emerging from an overloaded base
  prompt.
- **Narration segment:** Script 5:30–6:00.
- **Speaker notes:** Preview the hook boundary.
- **Animation:** Move one coherent procedure into its own card.
- **Technical accuracy notes:** None.
- **Instructor review:** None.
