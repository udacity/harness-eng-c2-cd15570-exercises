# Evaluation Rubric

## Acceptance rule

The controller accepts a candidate only when every required criterion passes.
Scores may support analysis, but no average can compensate for a failed hard
requirement.

## Core criteria

| ID | Criterion | Type | Required evidence | Pass condition | Failure feedback |
| --- | --- | --- | --- | --- | --- |
| D1 | Exact word count | Deterministic | Integer from `len(candidate.split())` | Count equals 60 | Report actual and expected counts |
| D2 | Incident identifier | Deterministic | Exact-match result for `INC-2048` | Identifier appears exactly | Name the missing identifier |
| D3 | Response shape | Deterministic | Parsed paragraph/list structure | One paragraph with no heading or bullet prefix | State the unexpected structure |
| I1 | Factual grounding | Inferential | Candidate claim mapped to incident field | Every factual claim is supported or clearly marked as hypothesis | Quote the claim and conflicting/missing evidence |
| I2 | Action-state consistency | Inferential | Candidate action/recovery claim mapped to Boolean/status state | No unobserved restart, rollback, recovery, or resolution is presented as completed | Name each unsupported state claim |
| I3 | Useful next step | Inferential | Candidate's proposed action and incident context | One concrete diagnostic step precedes production mutation | Suggest the missing kind of diagnostic action |

## Optional criterion scoring

For offline analysis, inferential criteria may use a 1–5 scale:

| Score | Meaning |
| ---: | --- |
| 5 | Fully satisfies the criterion; evidence is specific and consistent |
| 4 | Satisfies the criterion with a minor non-material omission |
| 3 | Partially satisfies it; an important detail is weak or missing |
| 2 | Substantial failure or unsupported reasoning |
| 1 | Direct contradiction, dangerous recommendation, or no relevant content |

For online acceptance, convert scores with a declared threshold and preserve
hard failures:

```text
inferential_pass = every required inferential criterion >= 4
overall_pass = D1 and D2 and D3 and inferential_pass
```

An action-state contradiction is a hard failure regardless of mean score.

## Evidence standards

### Sufficient evidence

- exact count or parser output for deterministic criteria;
- direct incident field and candidate excerpt for factual criteria;
- named next action and why it is safe/relevant;
- explicit “insufficient evidence” when a claim cannot be verified.

### Insufficient evidence

- “looks good”;
- confidence without a source;
- a total score with no criterion breakdown;
- the generator's explanation of what it intended;
- a claim that the evaluator is independent;
- or a pass inferred from missing/malformed output.

## Example criterion record

```json
{
  "criterion_id": "I2",
  "passed": false,
  "score": 1,
  "candidate_excerpt": "The rollback restored checkout service.",
  "authoritative_evidence": {
    "rollback_performed": false,
    "recovery_confirmed": false
  },
  "feedback": "Remove the rollback and recovery claim; neither action is confirmed."
}
```

## Calibration set design

Include at minimum:

- clearly passing examples;
- one-failure examples for every criterion;
- candidates with multiple simultaneous failures;
- concise and verbose variants with the same factual quality;
- correct candidates generated by multiple models;
- plausible but unsupported claims;
- ambiguous evidence that should escalate rather than pass; and
- evaluator outputs that are malformed or internally inconsistent.

Review false accepts first because they represent flawed candidates released by
the harness. Review false rejects to control unnecessary cost and escalation.
